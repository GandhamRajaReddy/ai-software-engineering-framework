# Cloud Infrastructure Engineering

Architectural patterns, security baselines, and automation workflows for production cloud environments.

## Infrastructure as Code (IaC) Standards

Every piece of cloud infrastructure must be declared in version-controlled code using **Terraform** or **OpenTofu**.

### Core IaC Principles

1. **Remote State with Distributed Locking**: Never store state files locally. Use S3/GCS with DynamoDB/etcd state locking to prevent concurrent apply collisions.
2. **Immutable Infrastructure**: Compute instances and container images are immutable. Configuration drift is resolved by deploying fresh images, never by mutating running servers.
3. **Strict Modularity**: Divide infrastructure into decoupled state workspaces: `networking` (VPC/subnets), `data` (PostgreSQL/Redis), `compute` (Kubernetes/ECS), and `security` (IAM/KMS).

## VPC Network Segmentation & Subnet Topology

Isolate workloads across three distinct network tiers:

```
Internet Gateway
       │
┌──────▼─────────────────────────────────────────────────┐
│ Public Subnet (ALB / Ingress Gateway / NAT Gateway)    │
│ Direct Internet Route (0.0.0.0/0 -> IGW)               │
└──────┬─────────────────────────────────────────────────┘
       │
┌──────▼─────────────────────────────────────────────────┐
│ Private Subnet (Application Workloads / Microservices) │
│ Outbound Internet via NAT Gateway; No Inbound from Net │
└──────┬─────────────────────────────────────────────────┘
       │
┌──────▼─────────────────────────────────────────────────┐
│ Database Subnet (PostgreSQL, Redis, RabbitMQ)          │
│ NO INTERNET ROUTE; Accessible ONLY from Private Subnet │
└────────────────────────────────────────────────────────┘
```

### Security Group Ingress Rules (Principle of Least Privilege)

- **Application Security Group**: Ingress allowed ONLY on port 8000/8080 from Ingress ALB Security Group.
- **Database Security Group**: Ingress allowed ONLY on port 5432 from Application Security Group.
- **Zero Public DB Access**: Database subnets must never have route table entries to an Internet Gateway or NAT Gateway.

## IAM Least Privilege & Zero Long-Lived Credentials

Never generate or store static IAM Access Keys (`AKIA...`) in config files, environment variables, or CI/CD pipelines.

1. **Workload Identity / IRSA**: Assign IAM roles directly to Kubernetes service accounts or ECS tasks via OIDC federation.
2. **Short-Lived STS Credentials**: Subprocess workloads receive 15-minute temporary STS credentials generated by the cloud provider metadata service.
3. **CI/CD Deployment via GitHub OIDC**: Use GitHub Actions OIDC provider to assume temporary deployment roles, eliminating static secrets in repository settings.

```yaml
# Secure GitHub Actions AWS Auth via OIDC
- name: Configure AWS Credentials
  uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: arn:aws:iam::123456789012:role/asef-github-ci-deployer
    aws-region: us-east-1
    audience: sts.amazonaws.com
```

## Secrets Management & Dynamic Secret Leasing

- **Centralized Secrets**: Store all database credentials, third-party API keys, and certificates in a managed secret store (AWS Secrets Manager or HashiCorp Vault).
- **Dynamic Secrets**: Vault generates unique, temporary database users for each application replica with automatic 1-hour TTL and lease renewal.
- **Zero Secrets in Disk Images**: Secrets must never be baked into Dockerfiles or committed to Git. Mount secrets in-memory as environment variables or tmpfs files at container runtime.

---

## Cloud Infrastructure Review Checklist

- [ ] All cloud resources defined in Terraform/OpenTofu with remote state locking.
- [ ] Subnets strictly segregated into Public, Private, and Isolated Database tiers.
- [ ] Database instances have no public IP and no route to the Internet.
- [ ] Static IAM user keys completely banned; Workload Identity and OIDC used everywhere.
- [ ] Multi-stage Docker builds enforce non-root user execution (`USER 10001:10001`).
- [ ] Secrets injected via managed secret manager with automated rotation.
